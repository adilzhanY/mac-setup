# Step 4: methods that can be run

A method is something you can run or follow: a command, a test, a named procedure, a
statistical test, a search query, a checklist. "Analyse carefully" and "think step by
step" are not methods; on current models, effort settings control thinking, not wording
(`sources/research_notes/prompting-evidence.md`).

## Name them at the level of a procedure

| Vague | Runnable |
|---|---|
| Review the security | Check each endpoint that verifies a password against the OWASP authentication cheat sheet, and probe it with a forged X-Forwarded-For header |
| Analyse the drop | Split the funnel by platform and week, check the sample ratio, and compare against the same weeks last year |
| Make it clearer | Put the main point in the first sentence (Minto), cut every sentence the reader cannot act on, read it aloud |
| Check the facts | Open every cited link and confirm the quoted sentence is on the page |

Name the tool by name: the test runner, the profiler, the linter, the ffmpeg filter, the
regulator's calculator.

## One estimate, a different way

Wherever there are numbers, add one rough figure worked out by another route: a Fermi
breakdown, or the result of similar past cases (the outside view, Tetlock; reference class
forecasting, Lovallo and Kahneman 2003). If the main result and the estimate are far apart,
one of them is wrong.

## The short killer list

Many fields have a few "killer items" that skilled people still skip under pressure, and
a short checklist at a set pause point catches them (Gawande 2009; in a before and after
study of a 19 item surgical checklist, deaths fell from 1.5 to 0.8 percent, Haynes et al.
2009). Each playbook's amateur mistakes section is that list
for its field. Check the result against it before calling it done.
