# kwx-deepen eval, 2026-11-03

Skill version 1.0.0. Cases 1, 2, 4, 5, 7 and 9 from `evals.json`. Each case ran twice in fresh general-purpose subagents: WITH (load kwx-deepen and follow it) and WITHOUT (no skills). Both were told not to edit files or run commands and to describe what they would fetch and run. One run per arm, so a single answer decides each cell. Treat the numbers as a signal, not a benchmark.

Grading is mine, by reading each answer against the case's assertions. Word counts are `wc -w` on the full answer as returned, including the rewrite block and any code.

## Fixes the failures point to

1. **Cap the deliverable, not just name it** (cases 5 and 9 grew 2.1x and 2.6x). Rule 1 says "same size, stated in units", but the agents stated a unit ("one recommendation plus the numbers", "one PR") that was loose enough to hold a simulation script or an IPv6 parser. Add to `method/rewrite.md`: state the size as the plain answer would be (word count or file and test count), and anything beyond it that is not the proof goes to Not doing. Add a check at the end: compare the deliverable to that number.
2. **Put the person's own inputs first in money and life decisions** (case 5 failed the one assertion the plain answer passed). In `fields/business.md`, make "ask for the person's numbers (income, savings, stay length, local listing)" a move with its own Check, ahead of fetching official rates. When a single input decides most cases, the gate's one question should ask for it.
3. **Move "growing delay" out of the Check line into the move itself** in `fields/software.md` move 4 (case 9 missed it). Write the move as "per account delay that grows with each failure, never a hard lock".
4. **Make the rewrite block fit the eval's 8 lines, or change the eval** (case 1). SKILL.md says at most 10 lines, `evals.json` says 8, and the run produced 13 because Moves wrapped to 5 lines. Pick one number and require Moves on one line.
5. **Skip silently** (case 7). The skip was right, but the agent announced it. Repeat in `method/gate.md` that a skipped run must not mention the skill or the method, and add that to eval 7's assertions.
6. **Fact check the playbook law claims against the primary text** (case 5 got the §23 EStG owner occupier exemption wrong while citing it). In `method/raw-material.md`, when a statute is named but not fetched, state the rule only as "to check" and never draw a consequence from it.
7. **Widen the description for implicit triggers and sibling skills** (6 trigger misses). Name the task types directly ("writing a post or letter, a spreadsheet or model, a video script, teaching a topic, choosing a tool, investigating wrong numbers") and say it runs before and alongside other skills ("feeds its rewrite into the skill that does the work"). Keep the skip clause as it is: it held on all 10 negatives.
