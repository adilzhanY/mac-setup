# AI slop tells

The signs that a UI was vibe coded or generated by an AI with no designer in the loop, and the fix for each. Sources: Kole Jain (vibe coded SaaS, dashboard flaws), Tim Gabe (premium apps), uxpeak (strawberry redesign). Kole's analogy: you can spot AI text by its em dashes, and you spot AI UI the same way, by its repeated defaults.

"Decent" is now the floor. Anything a tool produces for everyone (gradient hero card, ring chart, emoji greeting, floating "+") does not count as evidence of quality (Tim Gabe: "the commodity ceiling", "the minimalistic box house stage of user interfaces").

## 1. How to use this file

Before shipping, go through every table. For each tell, run the detection step on the code. Any hit is fixed before the work is called done. The detection column is written so it works without a screenshot.

## 2. Icons and imagery tells

| Tell | Detect in code | Fix |
|---|---|---|
| Emoji used as icons (checkmark, clipboard, eye, calendar, bar chart, phone, lock, sparkle, waving hand in a greeting) | `grep -rnP '[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]' src` | One interface icon library (Phosphor, Lucide or similar), line icons, one stroke weight. Emoji only where users pick them as content (Notion page icons) |
| Unicode symbols as icons (stars, check marks, arrows typed as characters) | Same grep, plus `grep -rnP '[\x{2605}\x{2713}\x{2714}\x{2192}\x{26A1}]'` | Real icons from the set; draw a custom icon on the same grid if the set lacks one |
| A decorative icon in every KPI tile and feature card, in a tinted disc | Search for icon wrappers with a tinted background repeated in a grid | Remove it. An icon must carry meaning (device type, brand logo, status) |
| Icon tile grid: a 3x2 grid of identical cards, tiny tinted icon square, title, two lines | A card map rendering icon plus title plus text, 6 items | One feature per section, text left and a real product visual right |
| Sparkle icon on every AI or "create" action | `grep -rni sparkle` | Remove unless the product's brand uses it consistently |
| Mixed icon styles (filled and outline, several colours, different weights) | Several icon imports or style props | One style, one colour, one weight |
| Icons larger than the text they label | Icon size token larger than the label line height | Icon size equals the line height |
| Stock or generated imagery with no focal point, mismatched across a catalog | Image components with no fixed aspect ratio or background | One image system: same background, light and framing |

## 3. Colour tells

| Tell | Detect in code | Fix |
|---|---|---|
| AI chosen palette: generic dark navy background (around #070b14, est.) with bright, clashing accents | Background hexes in the slate/navy range with unrelated bright accents | Pick the palette yourself. Near black tinted toward the brand hue (dark green for a green brand). "Never let an AI choose any of your colors." |
| Purple and violet gradients (hero cards, buttons, avatars) | `grep -rniE 'from-(purple|violet|indigo)|#7c3aed|#6366f1|#8b5cf6|linear-gradient'` | Solid brand colour from the ramp; gradients only with a brand reason |
| Gradient headline text (cyan into green, purple into pink) | `bg-clip-text`, `background-clip: text`, `text-transparent` | Plain bold headline in the text colour; one solid accent at most |
| Gradient CTA buttons | `linear-gradient` on button classes | One solid accent fill |
| Bright accent fill on every action ("Create New Link", "Export Report", "Generate") | Count accent buttons per screen | One accent fill per view; header actions dark neutral with an icon |
| Coloured borders and chips to tell plans or cards apart (green "Current", purple "Popular", purple bordered upgrade card) | Per item border colour props | Equal neutral cards |
| Data text in the brand colour (green monospace URLs) | Accent token on body data | Neutral text; accent for actions and live states |
| Neon saturated hues (#00FF00 like green, pure yellow) | Hex values with max saturation | Muted versions (olive, mustard, steel blue, plum, muted red) |
| Rainbow semantic soup: blue, green, purple, red icon colours on four KPI tiles | Per tile colour props | Colour from data only |

## 4. Layout and card tells

| Tell | Detect in code | Fix |
|---|---|---|
| The same KPIs repeated on several pages and in the sidebar | `grep` the KPI component; more than one route | One home per metric |
| Four KPI tiles in a row with small numbers (often 0) | A 4 column grid of stat cards | Two wide cards with label, chevron, big number, sparkline; or nothing |
| Cards that do nothing ("Choosing the Right Plan" explainer, tip cards with no action) | A card with neither a handler nor a data binding | Delete it |
| Cards inside cards | Card component rendered inside a card | Section header and white space |
| Sidebar with stat widgets | Metrics inside the sidebar component | Navigation only |
| No real page title, only a grey sentence ("Manage your links and view analytics") | Page without a title element | A real title ("Links") |
| Sparse tall flyout with one full width field per row | Side panel with stacked full width inputs and empty space | Centred modal with a two column grid |
| Everything centred, everything the same width | Every section `text-center` with `max-w` | Left aligned content and a real grid where content repeats |
| Generic 2x2 or 3x3 grids of equal cards for content that has a natural order | Grid of uniform cards | The form the data needs (list, timeline, chart) |

## 5. Component tells

| Tell | Detect in code | Fix |
|---|---|---|
| Gradient circle avatar with the user's initial | `charAt(0)`, `[0].toUpperCase()` inside a gradient circle | Account row: avatar or neutral person icon, name, chevron, popover with Billing and Usage, Settings, Sign Out |
| Separate Billing, Settings, Sign Out links in the sidebar | Several account links in nav | Into the account popover |
| A row of three buttons on every list item (Analytics, QR Code, Delete) | Count buttons in the row component | Three dot overflow menu; hover icons for quick actions |
| Text chips with emoji ("Verified Safe", "Copy") | Chip components with emoji or verbose labels | Icon only affordances with tooltips |
| Light grey filled inputs on a dark surface | Input background lighter than the surface in dark theme | Dark fill with a hairline border |
| Full width bright CTA at the bottom of every form | `w-full` primary in desktop modals | Sized to label, bottom right |
| Disabled button under a promo card ("Create Team" disabled beneath "Upgrade Required") | Disabled control with no path | One clear upgrade path, no dead controls |
| Floating centre "+" FAB and a tip card on a dashboard home | FAB plus tip card in the home layout | Only if the "+" is truly the main action; drop the tip card |
| ALL CAPS buttons, uppercase attribute labels | `uppercase` on buttons | Sentence case |
| Heavy, dark, tight drop shadows | Shadow tokens with high opacity and small blur | Low opacity, large blur |

## 6. Data and dashboard tells

| Tell | Detect in code | Fix |
|---|---|---|
| Equal weight label: value lists ("Restaurant: Chipotle / Item: Burrito Bowl / Total Cost: $32.45") | Repeated `Label:` then value rows | Logo, bold title, grey meta, accent on the key number, implied labels |
| Every table cell plain text | Cell renderers that only print the value | Chips, right aligned numbers, avatars, truncation, greyed inactive rows |
| Left aligned numbers | Numeric columns without right alignment | Right align, tabular figures |
| A time series as a sorted table | Table sorted by timestamp as the main view | Timeline or a summary chart above the table |
| One smooth decorative curve as the "chart" | Hard coded or smoothed sample data | Real data, real chart type, comparison toggle |
| Generic bar chart for geography | Bar chart of countries | Map plus a table with flags |
| KPI tiles and tabs that repeat the chart below | KPIs computed from the same series as the chart | Remove them |
| No tooltips, no sort, no filter, no row menu, no comments: a beautiful static table | Missing components | Design the invisible layer |
| Six bullet welcome modal | First login modal with a list | One tooltip on the key action, a corner checklist |

## 7. Copy tells

| Tell | Detect in code | Fix |
|---|---|---|
| Em dashes in UI copy | `grep -rnP '\x{2014}|\x{2013}' src` | Commas, full stops, colons, parentheses |
| Emoji greeting ("Good morning" plus a waving hand) | Emoji grep | Plain greeting or none |
| Slogans where information belongs ("Keep every session within reach!") | Exclamation strings in state views | Facts: count, plain headline, exact date |
| Generic CTA labels ("Submit", "Get Started", "Learn More" everywhere) | Repeated generic strings | Verb plus object plus outcome ("Search 12 Available Tables") |
| Lorem ipsum, "John Doe", "Acme", round fake numbers (1,234) | `grep -rnE 'Lorem|John Doe|Acme|1,234'` | Realistic content of realistic length |
| Redundant labels ("Price:") | Labels before self explaining values | Remove |
| Long badges ("20% OFF DISCOUNT") | Badge strings over 3 words | "20% off" |

## 8. Landing page tells

| Tell | Detect in code | Fix |
|---|---|---|
| Centred hero, gradient headline, boxed input card, "Success!" badge | Hero markup with gradient text | Left aligned hero, plain bold headline, grey one line subhead, input plus neutral action, product visual on the right |
| No real graphics, only icon tiles | No product imagery components | Your own product UI as the graphic: real components in skewed perspective (link cards), a tilted screenshot of a designed screen fading into the background |
| "LIMITED TIME OFFER" and "BEST VALUE" chips with no real end date | Static strings | Remove, or show the real end date |
| Logo row of famous brands that are not customers | Logo assets for Disney, Intel, Adobe... | Only real customers, or nothing |
| More than one bright CTA in the nav and hero | Count accent buttons | One ("Get Started Free") |

"Landing pages aren't about complexity, they're about presentation" (Kole Jain).

## 9. State and behaviour tells (the ones that matter most)

AI tools explain their design choices confidently, but about a quarter of that reasoning never reaches the interface, and what is dropped is system status, undo, and error recovery ("Design Theater", 2026, cited by Tim Gabe). These tells are invisible in a screenshot and the most expensive for users.

| Tell | Detect in code | Fix |
|---|---|---|
| Happy case only ("Prototype ... happy case, one HTML file") | Render function with only the data branch | Loading, empty, error, offline, limit states |
| Taps with no visible response | Handlers with no state change shown | Pressed state, spinner, confirmation |
| No undo for destructive actions | Delete handler with no undo or confirm | Undo toast or named confirm |
| Generic error ("Something went wrong") | One error string for every failure | Cause, next step, support path |
| Effort answered with nothing ("Looks like we didn't get enough content!") | Early return with only a message | Give something back and a next step |
| 80 screens that do not quite agree | Locally styled screens, duplicated components | Shared components; a side by side consistency pass |
| Design rationale in comments or docs that the UI does not implement | Comments claiming states that the code lacks | Audit stated reasoning against the built UI, state by state |

## 10. The final test

Ask: would an AI tool given the same one line prompt produce this same screen? If yes, what evidence of care is there beyond the look? Name three details that only exist because someone thought about this product and its users (a specific error message per reason, a preset from real data, a limit screen with the exact reset date). If you cannot name three, it is not done.
