# Kurtenbach and Buxton (1994), User Learning and Performance with Marking Menus

- **Citation:** Gordon Kurtenbach and William Buxton, Proceedings of CHI '94.
- **Copy read:** text version on Bill Buxton's site (billbuxton.com/MMUserLearn.html). PDF also hosted by Autodesk Research.
- **Used in:** `editors/shortcuts-and-command-search.md`, `editors/editor-foundations.md`, `editors/case-studies.md`.

## Study

Field study in ConEd, a real conversation-analysis editor, with six frequent commands in a marking menu. Two users over days and weeks, 5,237 logged selections.

## Findings

- Marks dominate with experience: user A used the visible menu in only 6.6 percent of 3,013 selections; user B in 45 percent of 1,945, with a sharp rise in mark use around selection 650 once she was comfortable with the setup.
- Frequent commands are marked more: frequency correlated with mark use (r squared 0.81 and 0.88).
- After breaks, users fall back to the menu, and these dips shrink with experience. "Expert users still switch back to menus to refresh their memory of menu layout."
- Speed: marks 0.18 s versus 1.10 s menu (user A). After subtracting the 0.33 s press-and-wait, menus were still about 3 to 4.2 times slower. "A mark will always be faster than menu selection, even if press-and-wait was not required."
- Another user made 16,026 selections in 36 hours; marks saved an estimated 3.66 hours.

## Design principles stated

Even number of items, up to 12; marks for frequent commands; use the mark's endpoints to combine object selection with the command; map directions to spatial meaning; let a command's inverse reuse the same mark. Marking menus are unsuitable for dynamic item lists.

## Lesson for the skill

The best expert path is one that novices practice by accident while using the slow visible path. Frequency of use should decide what gets the fastest gesture.
