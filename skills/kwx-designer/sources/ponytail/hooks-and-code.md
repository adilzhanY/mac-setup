## How ponytail sticks, in one picture

1. **SessionStart** (matcher `startup|resume|clear|compact`): `ponytail-activate.js` reads the default level (env, then config file, then `full`), writes a flag file, reads `skills/ponytail/SKILL.md`, filters it to the active level, appends a 2000 character codebase map, and prints it as hidden context. So the rules come back after every `/clear` and every compaction, not only at startup.
2. **SubagentStart**: `ponytail-subagent.js` reads the flag; if on, it injects the same ruleset into every subagent, because SessionStart context never reaches subagents. It must use the `hookSpecificOutput` JSON form or Claude Code drops it. Optional regex on `agent_type` scopes it.
3. **UserPromptSubmit**: `ponytail-mode-tracker.js` reads the prompt, switches level on `/ponytail lite|full|ultra|off`, persists a default on `/ponytail default X`, turns off only when the whole message is "stop ponytail" or "normal mode", and stays silent on every ordinary prompt. Hosts with no SessionStart (Qoder) get the full ruleset on every prompt from this hook instead.
4. **Statusline**: a 10 line shell script reads the flag and prints `[PONYTAIL]` or `[PONYTAIL:ULTRA]`. The session start hook offers to set it up once, then never again.
5. Every hook is fail open and never blocks: try/catch everywhere, exit 0, 5 s host timeout, 1 s self exit fallback when stdin never closes.
6. Sync: one canonical body (`AGENTS.md`) byte compared against 7 copies in CI; the longer `SKILL.md` is held to a list of load-bearing phrases; generated copies have a staleness test; seven manifests must share one version and match the release tag.

## What this means for kwx-designer: a permanent gate

Today the gate is permanent only on paper (`quality/quality-gate.md:3`). It reaches the agent when the skill triggers and the agent reads SKILL.md, and it reaches ui-designer only because its prompt says to read it. Compaction, a fresh subagent or a skipped skill load drops it. Ponytail's answer, translated:

1. **SubagentStart hook for ui-designer** (A2, A3, A4, A5, A6, A7). A node or python script in `~/.claude/hooks/`, registered in `settings.json` by merge (D7). It reads the 10 critical rules from `SKILL.md` and the `[critical]` rows from `quality/quality-gate.md` at run time, adds the titles of `~/.claude/ui-designer/mistakes.md`, starts with a marker line "KWX GATE ACTIVE", and prints the `hookSpecificOutput` JSON. Scoped to `agent_type` matching `ui-designer`, fail open on every doubt, try/catch, exit 0, 5 s timeout.
2. **SessionStart hook with `startup|resume|clear|compact`** (A1) that injects only a 3 line pointer ("UI work goes through ui-designer, run quality/quality-gate.md before done, report in section 13 format"), so the main agent keeps the rule after compaction without paying for 16 KB every session.
3. **Optional UserPromptSubmit reminder** (A9, A11) that fires only on clear UI prompts (whole word matches tested against near misses like "add a normal mode toggle"), silent otherwise.
4. **Optional design system map** (A18, D3) for ui-designer: token files, component names, custom icon names, inside a character budget, names only, no raw file text.
5. **`scripts/check_skill.py`** (B1, B2, B5, B6, B7, B8, B10, B11): table paths exist and every md is listed; invariant phrases present in SKILL.md, quality-gate.md and ui-designer.md; section 14 greps run against a fixtures folder with hits and non-hits; description and size budgets; no em or en dashes; both scripts' `--selftest` pass. Run it from `arch-config-push` or a pre-commit hook (B12).
6. **Graded evals** (C1, C2, C3): one passing and one failing sample per mechanical assertion in `evals/evals.json`, with a small grader, so the eval proves it can tell a passing UI answer from a failing one.
7. **Do not add gate levels** (A24). If depth ever varies, vary depth, never whether the gate runs.
