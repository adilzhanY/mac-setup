# Tauri 2 desktop apps

Tauri 2 apps have a Rust backend and a web view frontend (React, Svelte, plain TS). The Rust side owns data, files and money; the web view calls it through commands. kwx-developer had no Tauri coverage before 1.1.0. In the 2026-11-01 trial the skilled desktop build had no test of the IPC argument contract and a README tied to the build machine; the build without skills drove the real command layer in tests but passed raw file paths from the web view. This file keeps the good half of each.

Read `rust.md` first for the general Rust rules; this file covers only what is specific to Tauri. Check the installed `tauri` version in `src-tauri/Cargo.lock` and read its docs before writing test or plugin code: names in `tauri::test` and the plugins changed between 2.x minor releases.

## 1. Commands are the API

- Every `#[tauri::command]` is registered in one `tauri::generate_handler![...]` list, in `lib.rs`. One list, one place; a command that is defined but not registered fails only at run time, in the UI.
- Arguments arrive camelCase from JS (`projectId`) and are snake_case in Rust (`project_id`) unless the command sets `rename_all`. Pick one convention for the whole app and record it in Decisions. A wrong argument name is not a compile error on either side.
- Commands return `Result<T, E>` where `E` serializes to a stable machine code the UI maps to a state (the duet states list, `workflow/duet-with-kwx-designer.md` section 2). Never return a bare `String` error the UI has to parse.

```rust
#[derive(Debug, thiserror::Error, serde::Serialize)]
#[serde(tag = "code", content = "detail", rename_all = "snake_case")]
pub enum AppError {
    #[error("project not found")] ProjectNotFound,
    #[error("a timer is already running")] TimerRunning,
    #[error("the preview changed, review it again")] StalePreview,
    #[error("storage failed")] Storage(String), // the message is for logs; the UI shows copy per code
}

#[tauri::command]
async fn start_timer(state: tauri::State<'_, AppState>, project_id: i64) -> Result<Entry, AppError> { /* ... */ }
```

- Commands are thin: parse, call the domain module, map the error. Domain logic lives in plain Rust modules with their own unit tests, so it is testable without Tauri.

## 2. Contract test, required

The web view and Rust agree only by string names. Prove the agreement with one of these, and add the name diff test in every case.

1. **Generated bindings.** `tauri-specta` or `ts-rs` generate the TypeScript functions and types from the Rust commands, so the frontend cannot call a missing command or pass a wrong argument name without a type error. The generated file is checked in and regenerated by a test or a build step that fails when it is stale.
2. **IPC test through the real command layer.** With the `test` feature on the `tauri` dev dependency, invoke each command with the exact argument object the frontend's `api.ts` sends:

```rust
#[cfg(test)]
mod ipc_tests {
    use tauri::ipc::{CallbackFn, InvokeBody};
    use tauri::test::{get_ipc_response, mock_builder, mock_context, noop_assets, INVOKE_KEY};
    use tauri::webview::InvokeRequest;

    #[test]
    fn start_timer_takes_the_argument_names_the_frontend_sends() {
        let app = mock_builder()
            .manage(super::AppState::in_memory())
            .invoke_handler(tauri::generate_handler![super::start_timer])
            .build(mock_context(noop_assets()))
            .unwrap();
        let webview = tauri::WebviewWindowBuilder::new(&app, "main", Default::default()).build().unwrap();
        let res = get_ipc_response(&webview, InvokeRequest {
            cmd: "start_timer".into(),
            callback: CallbackFn(0),
            error: CallbackFn(1),
            url: "http://tauri.localhost".parse().unwrap(),
            body: InvokeBody::Json(serde_json::json!({ "projectId": 1 })), // copied from api.ts
            headers: Default::default(),
            invoke_key: INVOKE_KEY.to_string(),
        });
        assert!(res.is_ok(), "{res:?}");
    }
}
```

3. **Name diff test**, always: the commands the UI calls equal the commands registered.

```ts
// src/api.contract.test.ts
import { expect, test } from "vitest";
import { readFileSync } from "node:fs";
const api = readFileSync("src/api.ts", "utf8");
const lib = readFileSync("src-tauri/src/lib.rs", "utf8");
const called = new Set([...api.matchAll(/invoke(?:<[^>]*>)?\(\s*"(\w+)"/g)].map((m) => m[1]));
const list = lib.match(/generate_handler!\[([^\]]*)\]/s)?.[1] ?? "";
const registered = new Set(list.split(",").map((s) => s.trim().split("::").pop()).filter(Boolean));
test("every command the UI calls is registered, and none is left unused", () => {
  expect([...called].sort()).toEqual([...registered].sort());
});
```

## 3. File access stays in Rust

- Open save and open dialogs from Rust: the command calls `tauri-plugin-dialog` itself and gets the path from the dialog, then reads or writes the file. The web view only says "export last month", never where.
- Never accept a raw file path from the web view (`path: String`, `PathBuf` arguments). A compromised or buggy web view can then read or overwrite any file the user can.
- Grant the web view no `fs` or `dialog` capability. Plugin calls made from Rust need no web view permission.

```rust
#[tauri::command]
async fn export_csv(app: tauri::AppHandle, state: tauri::State<'_, AppState>, from: String, to: String)
    -> Result<Option<u32>, AppError> {
    use tauri_plugin_dialog::DialogExt;
    let Some(file) = app.dialog().file().add_filter("CSV", &["csv"]).set_file_name("hours.csv").blocking_save_file()
    else { return Ok(None) }; // the user cancelled
    let path = file.into_path().map_err(|e| AppError::Storage(e.to_string()))?;
    let rows = state.export_rows(&from, &to)?; // the same price() as the invoice (section 6)
    write_csv_for_excel(&path, &rows)?;
    Ok(Some(rows.len() as u32))
}
```

## 4. Least capabilities

- `src-tauri/capabilities/*.json` lists only what the UI calls. Review the default capability file the template creates: remove `fs`, `shell`, `dialog` and `http` permissions the web view does not use.
- Keep the content security policy in `tauri.conf.json` strict (no remote scripts); the web view loads only the bundled frontend.
- One window, one capability file, unless the app really has windows with different rights.

## 5. Data

- SQLite in the app data dir (`app.path().app_data_dir()`), set up as in `data/sqlite-and-local-first.md` (pragmas, IMMEDIATE write transactions, STRICT tables). Set `PRAGMA application_id` to a fixed number for the app's files.
- Backup with `VACUUM INTO` and a restore that first checks `PRAGMA application_id` and `PRAGMA integrity_check` on the chosen file, then makes a safety copy of the current database, then swaps (`data/backups-and-recovery.md` section 6).
- Preview then confirm steps (an invoice preview, an import preview) carry a preview hash (`data/transactions-and-integrity.md` section 3).

## 6. Money, dates and exports

Rust code follows `languages/typescript/dates-and-money.md` the same way:

- One `price()` in the domain module, used by the overview, the CSV and the invoice, with one rounding step. A test asserts CSV net sum equals invoice net for the same entries.
- Times that belong to a place use that place's zone (`chrono-tz` or `jiff` with an IANA name), never the machine zone.
- The zero duration rule: an entry with start equal to stop is dropped or refused by a written, tested rule, never priced as a 0:00 line.
- CSV for people: labels, semicolons, BOM, CRLF and formula neutralising (`data/backups-and-recovery.md` section 13).

## 7. Build notes and the README

- The README names `CARGO_TARGET_DIR` only as an optional env var ("set `CARGO_TARGET_DIR` to build on another disk"), never a machine path.
- No shell dialect specific lines (fish `set -x`, zsh only syntax), no user names, no "on this machine" notes. Gate section 13 (K3) checks it.
- Name the system packages Tauri needs per OS (webkit2gtk 4.1 on Linux) and the commands: `pnpm tauri dev`, `pnpm tauri build`, `cargo test --manifest-path src-tauri/Cargo.toml`.

## 8. Checks

| Check | Pass condition | How to verify |
|---|---|---|
| Commands registered once | one `generate_handler!` list outside test code | `rg -n "generate_handler!" src-tauri/src` shows one hit outside `#[cfg(test)]` modules (the IPC test of section 2 builds its own list) |
| Contract test present | generated bindings or an IPC test, plus the name diff test | `rg -n "get_ipc_response\|specta\|ts_rs" src-tauri src`; the diff test passes |
| No raw path commands | every path comes from a dialog inside Rust | `rg -n "path: String\|PathBuf" src-tauri/src` and review each hit |
| Capabilities minimal | only permissions the UI calls; no `fs` or `dialog` for the web view | read `src-tauri/capabilities/*.json` |
| Restore guarded | application_id and integrity checked, safety copy made | read the restore command and its test |
| One pricing function | overview, export and invoice share `price()` | `rg -n "fn price" src-tauri/src` shows one definition |
| README portable | no machine paths or shell dialect | gate K3 (the README block under the K table) prints nothing |
